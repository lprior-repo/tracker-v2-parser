# SQL correctness audit — November 21, 2026

## Scope

This audit covers result persistence, sparse replays, concurrent published-file revisions and export observation limits in `tracker-v2-parser`. The checkout started at `51395463f3ad8a58c3f435775c5584a974f1d393`; this is an additive SQL change set on that base. The earlier Class of 2028 preparation patch is separate and is not reconstructed here.

The campaign target remains graduation year 2028 for Michigan, Minnesota, Iowa, Illinois and Colorado. Graduation year is distinct from competition season and a source's reported grade. These persistence fixes apply across cohorts; the new export-limit scenarios explicitly select graduation year 2028.

All database execution used a disposable PostgreSQL 18.1 instance, ordinary application test role and isolated schemas. No live athlete database was inspected or modified, and no public-provider scrape was started.

## Confirmed defects and corrections

| Defect | Reproduced outcome | Correction |
| --- | --- | --- |
| Sparse first insert races with a complete insert | Event and mark survived, but normalization became null and status became `unclassified`. Both assigned and unassigned persistence were exercised. | The missing-row attempt may insert but cannot update a concurrent winner with stale normalization. A guarded conflict locks the winning row, followed by one fresh read and retry. |
| Published-file revisions overlap through different page identities | Two captures of the same MileSplit file both remained current because neither revision query saw the other's uncommitted rows. | Acquire sorted transaction locks for proven file identities before adoption, domain writes and reconciliation. The earlier capture's missing rows remain retained with `unverified_prior_revision`. |
| Rust and SQL disagree about blank strings | Tab-only replay replaced the stored event, mark and metadata while numeric normalization still represented the earlier published mark; raw failure evidence was also cleared. | Use the Rust-compatible Unicode whitespace set in every blank predicate in both upsert statements. Preserve nonblank text verbatim and preserve the newly captured raw source evidence separately. |
| Export count guard deduplicates before applying its limit | The original plan consumed all 100,000 observations to return a capped count of 10,001. | Use `UNION ALL` for physical and valid reviewed ownership branches, which are internally unique and mutually disjoint under the current schema/view contract. |

The sparse fix does not preserve old normalization blindly. The regression changes the event from a time event to long jump and verifies conversion from nanoseconds to micrometers. A separate DQ scenario verifies that explicit failure status clears numeric normalization. Complete batches explicitly disable the missing-row conflict guard.

Published-file locks are scoped to the current schema and have a separate namespace. A page accepts at most 64 distinct proven files; normal raw captures identify one. The file lock survives through the enclosing page transaction and is released on commit or rollback. Pages without proven raw files add no lock query. There is no advisory lock per result.

The assigned sparse race tests the supported public persistence contract. The unassigned races and the file-alias race additionally use source parser output. The tests retain durable capture/parse references, verify receipts and replay both operations without additional mutations. Gate polling and the joined writes have finite deadlines, and the gate connection is explicitly released and closed.

## Count-guard measurement

Both query variants matched all ten explicit count oracles, including empty, below-limit, exact-limit, over-limit, mixed-ownership and reviewed-only fixtures. The PostgreSQL instance used 4 MiB `work_mem` and the checked-in schema and indexes.

| Measurement for 100,000 physical observations | Original `UNION` | Revised `UNION ALL` |
| --- | ---: | ---: |
| Result rows consumed | 100,000 | 10,001 |
| Query-level shared-buffer hits | 5,642 | 568 |
| Median execution time, three alternating trials | 40.830 ms | 3.324 ms |

Original times were 34.657, 40.830 and 71.494 ms; revised times were 3.489, 3.324 and 2.121 ms. Rust compilation ran concurrently. These results describe this fixture and query, not overall production throughput. `UNION ALL` permits early termination but does not guarantee a hard input-scan bound for every plan or data distribution.

The measured revised SQL SHA256 is `18cc1bf51d664060d273b3a5af326eca761e918251d6da90c65dd8080dea60c0`. Reproduction instructions and the ownership-disjointness proof are in [the PostgreSQL performance contract](postgresql-performance.md). The delivery evidence includes the exact original/revised SQL, JSON execution plans, fixture SQL and counts.
